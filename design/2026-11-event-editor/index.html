Choose the dates. Shape the time.

Keep the custom sequence and its clickable month preview, then make arranging times feel as direct as the main calendar. These three native prototypes explore different ways to do that.

Already changed in the application

  • Relative time steps: +45min, +2h, and multipliers such as 3*+30min. m still means months.
  • Calendar choices show their source color; preview events use the chosen calendar’s color.
  • The old added/skipped-date symbols and their legend are removed.

For review: the larger time-editing workflow

The layouts below are separate experiments. Start + duration, integrated date selection and visual per-occurrence time editing have not replaced the application’s dialog yet.

The screenshots and interactive windows use synthetic events. The prototypes do not save or sync changes.

Three ways to arrange the same series

A common starting point: dates remain editable through the sequence or month preview, duration belongs to the series, and an individual event can have its own starting time.

A Month + day planner

Keep the month in sight and arrange the selected day in a vertical time column. Select an event, then move it to a different starting time.

B Month ↔ week

Use Month to choose the dates; switch the same preview to Week to arrange times using a familiar calendar grid.

Fits: comparing and moving several events within a week.

The time grid has more room and shows relationships across days. Dates far apart require changing the page or switching back to Month.

One large calendar · switch Month / Week

C Month + time ribbons

Keep the month and compare times along horizontal rulers. Event blocks show where each selected day falls within the day.

Fits: spotting and adjusting different times on dates spread across a month.

Several dates can be compared without changing the month. The horizontal time direction differs from the main calendar and needs more care for overnight events.

Persistent month overview · compare daily time ranges

I would start with A if preserving the current date-picking workflow is the priority. It adds the main calendar’s familiar time axis without replacing the month. B is a stronger candidate if arranging a busy week matters more. C is worth trying if comparing hours across scattered dates is the main task.

Interaction details

These examples focus on editing one occurrence and on the optional End control. Detail screenshots use the light appearance.

The shared direction

One calendar for picking dates

The Start date control uses the preview already in the dialog. There is no second miniature calendar to open and reconcile with it.

Visual first, precise typing available

Move an event against the time axis to choose its start. A simple clock field remains available for a precise value such as 09:35.

Dates and individual occurrences have different targets

The month still adds and removes dates. Selecting an event chip targets that occurrence’s time, so other events on the same date remain independent.

Keep the sequence as the editable representation

Visual changes produce a compact equivalent sequence. The time controls complement the language, including min and h, instead of replacing it with a list of dates.
