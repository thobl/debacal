# debacal 0.1.2

- Fix source checkouts loading an older system-installed Debacal in virtual
  environments with system package access. Editable installs now consistently
  use the checkout, including the `debacal` console command.
- Support embedded VTIMEZONE rules, including Windows timezone identifiers,
  throughout import, editing, storage and synchronization.
- Improve standard calendar interoperability: floating times and durations,
  daylight-saving transitions, RDATE periods with individual durations, leap
  seconds, quoted parameters and malformed-event isolation.
- List failed imports individually with event details, original-source viewing
  and export, copied diagnostics, and reviewed retries of retained local imports.

## Install or update

Fully quit Debacal before updating so the next launch loads the new code.
Existing profiles, settings and stored passwords are retained.

**Arch release:** extract `debacal-0.1.2-arch.tar.gz`, review `PKGBUILD`, and run
`makepkg -sif`. It downloads and verifies the matching source archive.

**Arch checkout:** from the repository root:

```sh
git pull --ff-only
cd packaging/arch
makepkg -p PKGBUILD.local -sif
```

**Other Linux distributions:** install pipx, then run:

```sh
pipx install --force https://github.com/thobl/debacal/releases/download/v0.1.2/debacal-0.1.2-py3-none-any.whl
```

**Source checkout with uv:** run `uv sync --extra dev`, then
`uv run debacal --test` to use the separate testing profile. This updates the
checkout's environment; system installations remain managed separately.

Python 3.11+ and icalendar 6.3+ are required. Source, wheel, Arch recipe and
SHA-256 sums are attached. See the
[installation guide](https://github.com/thobl/debacal/blob/v0.1.2/docs/INSTALL.md)
and [calendar format support](https://github.com/thobl/debacal/blob/v0.1.2/docs/CALENDAR_STANDARDS.md).
